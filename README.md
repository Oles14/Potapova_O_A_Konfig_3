# Практическая работа №3

Конфигурационное управление. Вариант 19.

## Описание

Разработка ассемблера и интерпретатора учебной виртуальной машины на Python.

## Реализованные этапы

1. Перевод CSV-программы в промежуточное представление.
2. Формирование машинного кода и запись двоичного файла.

## Команды ассемблера

| Команда | Код | Размер | Назначение |
|---|---|---|---|
| LOAD,B,C | 4 | 5 байт | M[C] = B |
| READ,B,C,D | 9 | 5 байт | M[B] = M[M[D] + C] |
| WRITE,B,C | 0 | 4 байта | M[B] = M[C] |
| SHR,B,C,D | 3 | 5 байт | M[M[D]] = M[C] >> M[B] |

M — память виртуальной машины.

Исходная программа записывается в формате CSV без заголовков. Машинный код формируется в порядке little-endian.

## Функции

- parse_command — разбор и проверка команды.
- parse_program — чтение CSV-программы.
- get_spec — поиск спецификации по коду операции.
- encode_command — кодирование одной команды.
- assemble_program — кодирование всей программы.
- print_program — вывод машинного кода.
- main — обработка аргументов и запуск.

## Параметры

- --input — путь к исходному CSV-файлу.
- --output — путь к выходному двоичному файлу.
- --test — вывод машинного кода в шестнадцатеричном формате.

## Запуск

`python -m src.assembler --input tests/specification.csv --output program.bin --test`

В Windows также можно использовать run.bat.

Требуется Python 3. Дополнительные библиотеки не нужны.

## Тестирование

`python -m unittest discover -s tests -v`

Проверяются разбор команд, формирование машинного кода и создание двоичного файла.

## Пример

Исходная команда: LOAD,398,423

Промежуточное представление: (4, 398, 423)

Машинный код: 0xE4, 0x18, 0x00, 0x4E, 0x03

Размер команды: 5 байт.

Размер тестовой программы specification.csv после ассемблирования: 19 байт.
